# Автоматическая статистика «Реликтового роя»

Клиент работает на GitHub Pages без отдельного сервера. Для сбора данных **со всех устройств** нужно развернуть бесплатный Cloudflare Worker + D1. Отчёты не скачиваются и не отображаются в игре.

## Что записывается

При включённом согласии игрока отправляются:
- Каждые ~30 **игровых** секунд: время, сложность, уровень, HP, убийства, враги на экране, урон боссам, агрегаты FPS, задержки кадра и времени JS update/render
- В конце забега: результат, счёт, оружие и его улучшения, выбор карточек, синтезы, события боссов, история боя и разреженная временная шкала производительности

Без IP-адресов в базе, User-Agent, логинов, геолокации, cookies, persistent player ID и текстового ввода. \`sessionId\` создаётся заново для каждого забега, \`eventId\` предотвращает повторы после потери сети. При отказе от аналитики сообщения не отправляются. Приёмник ограничивает набор полей и размер сообщений. Административные API требуют секретный токен.

## Подключение (один раз)

1. Создайте бесплатный аккаунт Cloudflare, установите Node.js (20+) на свой компьютер.
2. В корне репозитория выполните:
   \`\`\`bash
   npx wrangler login
   npx wrangler d1 create relict-swarm-telemetry --location weur
   \`\`\`
3. Скопируйте \`telemetry/wrangler.toml.example\` в \`telemetry/wrangler.toml\`. Вставьте UUID, выданный Cloudflare, вместо \`REPLACE_WITH_YOUR_D1_DATABASE_UUID\`. Не вносите учётные данные в GitHub.
4. Создайте таблицы:
   \`\`\`bash
   npx wrangler d1 execute relict-swarm-telemetry --remote --file=telemetry/schema.sql --config telemetry/wrangler.toml
   \`\`\`
5. Создайте надёжный секрет для доступа к статистике (не менее 24 случайных символов):
   \`\`\`bash
   npx wrangler secret put ADMIN_TOKEN --config telemetry/wrangler.toml
   \`\`\`
   Вставьте секрет при запросе. **Не помещайте его в файл клиента, код игры или GitHub.**
6. Разверните сервер:
   \`\`\`bash
   npx wrangler deploy --config telemetry/wrangler.toml
   \`\`\`
7. Cloudflare выдаст URL вида \`https://relict-swarm-telemetry.<subdomain>.workers.dev\`. Впишите в публичный файл **\`telemetry-config.js\`** только путь приёма:
   \`\`\`javascript
   window.RELIC_TELEMETRY_CONFIG = {
     endpoint: 'https://relict-swarm-telemetry.<subdomain>.workers.dev/ingest'
   };
   \`\`\`
   Здесь нужен реальный адрес, а не пример. Этот URL не секрет.
8. Проверить клиент в \`develop\`, открыть сайт по HTTPS, разрешить анонимную статистику в появившемся окне и начать забег. Потом публиковать в \`main\`, а не наоборот.

**Важно:** в \`develop\` адрес пока пустой. До шага 7 данные собираются только локально в игровом браузере; централизованная отправка невозможна. Ни Worker, ни D1 не создаются самостоятельно через GitHub.

## Как посмотреть результаты

Административные запросы запускаются с компьютера; они не доступны через игровое меню.

\`\`\`bash
# Вставьте адрес Worker и свой секрет в команду локально
curl -H "Authorization: Bearer YOUR_ADMIN_TOKEN" \
  "https://YOUR_WORKER_URL/admin/summary"
curl -H "Authorization: Bearer YOUR_ADMIN_TOKEN" \
  "https://YOUR_WORKER_URL/admin/events?limit=20"
\`\`\`

\`/admin/summary\` показывает число событий, забегов, средние FPS и распределение по устройствам/сложности. \`/admin/events\` отдаёт последние события и детальные финальные отчёты для анализа баланса.

Для Windows PowerShell используйте \`curl.exe\` вместо \`curl\` или Invoke-RestMethod с заголовком Authorization.

## Ограничения

- Cloudflare Workers и D1 имеют бесплатные лимиты. При превышении лимитов сервер перестанет принимать данные до их сброса или увеличения лимита. Это **не должно ломать игру**: клиент оставит небольшой хвост событий в локальной очереди.
- GitHub Pages не может принимать и централизованно хранить POST-запросы игроков без дополнительного сервиса.
- Нужна HTTPS-страница и CORS. В Worker разрешены \`https://barvolar.github.io\`, \`http://localhost:4173\` и \`http://127.0.0.1:4173\`. На новых доменах нужно обновить перечень.
- Cloudflare автоматически обрабатывает сетевые запросы, хотя наш код не сохраняет IP и User-Agent в D1.
- Endpoint открыт для игровых событий без личной авторизации. Ограничение Origin не защищает от подделок вне браузера. Для массового публичного релиза настройте rate limiting/WAF и следите за расходом ресурсов.
- Согласие можно отозвать в настройках. Отзыв прекращает дальнейшую отправку и очищает локальную очередь, но не удаляет уже полученные события на сервере.
