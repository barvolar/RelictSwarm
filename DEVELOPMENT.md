# Разработка «Реликтового роя»

**Рабочая ветка:** `develop`. Публикуемая версия GitHub Pages находится в `main`; перенос её не изменяет.

## Запуск и проверка

Требуется бесплатный Node.js 20+. В проекте **нет npm-зависимостей**, Vite и платных сервисов.

```bash
npm run build
npm test
npm run preview
```

Предпросмотр: http://127.0.0.1:4173/ после команды `npm run preview`. Готовая игра вместе с файлами телеметрии лежит в `dist/`.

Для GitHub Actions: откройте последний успешный запуск **Build and verify modular game** для `develop` и скачайте **RelictSwarm-test-build** из раздела Artifacts. Распакуйте архив целиком, затем откройте `index.html`.

## Архитектура исходников

Сборка содержит **75 упорядоченных JS-частей**, **8 частей CSS** и **6 самостоятельных ES-модулей чистой логики**. Это **не 78 независимых ES-модулей**: большинство игровых частей пока исполняется в общей области видимости внутри одного IIFE, что преднамеренно сохраняет обратную совместимость.

| Каталог | Ответственность |
| --- | --- |
| `src/modules/10-data/weapons/` | Каталог оружия, улучшения, утилиты |
| `src/modules/10-data/world/` | Враги, синтезы, прогрессия, волны |
| `src/modules/20-core/state/` | Сохранения, состояние, скины, графика |
| `src/modules/20-core/input/` | Клавиатура, сенсорный джойстик, кнопки |
| `src/modules/30-audio/engine/` | Настройки, микшер, музыка, фоновые звуки, огнемёт, SFX |
| `src/modules/30-audio/embedded-bank.js` | Встроенная библиотека аудио без внешних загрузок |
| `src/modules/40-game/training/` | Полигон: симуляция и панель |
| `src/modules/40-game/lifecycle/` | Запуск/пауза, результаты, движение |
| `src/modules/40-game/entities/` | Спавн, статусы, урон, смерть, прогресс игрока |
| `src/modules/40-game/upgrades/` | Выбор улучшений, карточки, применение, кузница |
| `src/modules/40-game/combat/` | Наведение, атаки синтезов, дроны, снаряды |
| `src/modules/40-game/enemies/` | Поведение врагов, атаки боссов, опасности, дроп, рейды |
| `src/modules/40-game/update/` | Симуляция и HUD |
| `src/modules/50-ui/pages/` | Меню, прогрессия, скины, настройки, магазин, справка |
| `src/modules/60-analytics/` | Баланс, FPS, отчёты, экспорт, графические настройки |
| `src/modules/70-render/layers/` | Слои отрисовки, игрок, враги, эффекты, сборка кадра |
| `src/modules/90-bootstrap/` | Игровой цикл, тестовый мост, запуск |
| `src/styles/sections/` | Базовые стили, синтез, HUD, телефоны, настройки |
| `src/domain/` | Шесть независимых ES-модулей вычислительных правил |

Состав и **точный порядок исполнения** JS определяются `src/module-order.json`, CSS — `src/style-order.json`. Сборщик `scripts/build.mjs` соединяет их в единый HTML, встраивая экспорты чистых модулей. **Не меняйте порядок частей без тестирования**: инициализация чувствительна к нему.

Шесть модулей в `src/domain/`: `targeting.mjs`, `fusion-rules.mjs`, `boss-damage.mjs`, `weapon-damage.mjs`, `weapon-cooldown.mjs`, `fusion-transfer.mjs`. Они тестируются напрямую как ES-модули. Игровые части ещё не переведены массово на `import/export`, чтобы не сломать изменяемое общее состояние.

## Тесты и гарантия отсутствия изменений

`npm test` собирает игру, проверяет синтаксис и запускает тесты игровой логики и структуры проекта.

Предыдущая контрольная сумма относилась к версии до изменения системы аналитики. После намеренных правок клиентского кода побайтовое совпадение не ожидается, и историческая проверка рефакторинга больше не используется.

Нормальные тесты не заменяют реальный 15-минутный забег, проверку WebAudio, касаний, производительности и сохранений на Android/iPhone. Для публикации в `main` нужен успешный CI и ручная проверка.

## Как теперь вносить изменения

Изменяйте нужную часть в `src/modules/`, чистые формулы — в `src/domain/`, CSS — в `src/styles/sections/`. Не редактируйте `dist/index.html`: он генерируется заново. Не изменяйте `main` до проверки и Pull Request. Не добавляйте ключи Cloudflare и другие секреты в публичный JavaScript.

Для будущих небольших игр и офлайн-запуска единый итоговый HTML остаётся практичным. Отдельный Vite/ESM runtime на этом этапе не нужен, пока он не принесёт реальную пользу и не будет проверен на целевых устройствах.

## Автоматическая телеметрия

В игре больше нет FPS-панели, кнопок скачивания технических JSON-отчётов и экранов диагностики. Измерение FPS/CPU и сбор событий баланса продолжаются скрыто. Снимки каждые ~30 игровых секунд и итог забега отправляются через `telemetry-client.js` **только после согласия** игрока и настройки публичного HTTPS endpoint в `telemetry-config.js`. При отсутствии endpoint данные остаются локальными. Подробная инструкция по Cloudflare Worker + D1: [telemetry/README.md](telemetry/README.md).

Контрольные тесты теперь включают серверный приём, фильтрацию данных, CORS, защиту админ-API и отсутствие элементов диагностики в собранной игре. **Не выкладывать в `main` без ручного теста.**
