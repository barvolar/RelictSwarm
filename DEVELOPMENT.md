# Разработка «Реликтового роя»

Рабочая ветка: **develop**. Публичный GitHub Pages продолжает обслуживаться из **main**.

## Сборка

Требуется Node.js 20+. Никаких npm-зависимостей, платных библиотек или серверов.

```bash
npm run build
npm test
npm run preview
```

Готовая игра находится в `dist/`, предпросмотр: http://127.0.0.1:4173/. Для публикации использовать **содержимое dist**, а не папку src.

## Системы

- `src/index.template.html`: разметка экрана
- `src/styles/game.css`: стили, мобильная адаптация
- `src/modules/10-data/`: оружие, враги, боссы, синтезы и волны
- `src/modules/20-core/`: ввод и состояние
- `src/modules/30-audio/`: звуковая библиотека и воспроизведение
- `src/modules/40-game/`: боевые механики, прокачка, спавн и игровой цикл
- `src/modules/50-ui/`: меню, настройки
- `src/modules/60-analytics/`: FPS и баланс
- `src/modules/70-render/`: графика
- `src/modules/90-bootstrap/`: запуск
- `telemetry-client.js`, `telemetry-config.js`: опциональная отправка статистики

Очередность соединения исходников задаётся `src/module-order.json`.

## Важное о миграции

Это переходный этап: **основные файлы всё ещё связаны общей областью видимости**, но правила выбора цели и доступности синтеза уже вынесены в независимые ES-модули. Остальная часть игры сохраняет прежний порядок выполнения, а изменения проверяются автоматическими тестами.

`npm test` собирает автономный HTML, проверяет синтаксис JavaScript, а затем запускает 11 регрессионных тестов реальной игровой логики из `tests/gameplay.test.mjs`. Среди тестов: оружие, рецепты, редкости, прокачка, синтез, приоритет атаки босса, лимит пил и сохранения. Тесты не заменяют ручной мобильный тест полного забега, звука и FPS.

Два чистых независимых ES-модуля вынесены в `src/domain/`: `targeting.mjs` (приоритет босса) и `fusion-rules.mjs` (доступные рецепты). Node.js импортирует их напрямую при тестировании. Сборщик временно встраивает их экспорты внутрь исходного IIFE, так что конечный `dist/index.html` остаётся самодостаточным и не требует сетевых запросов/импортов. Это переходная сборка: другие игровые системы ещё связаны общей областью видимости. Следующее извлечение выполнять только после тестов.

Исторический `src/baseline.sha256` сохранён как свидетельство первого этапа миграции, но проверка побайтового совпадения с v0.10.15 больше не запускается: изменённый игровой исходник закономерно создаёт другой HTML. Оставшиеся игровые системы будем переводить на независимые ES-модули постепенно. Полноценный бандлер (например, Vite) имеет смысл подключать только после дальнейшего выделения интерфейсов и проверки сборки.

**Не изменять main без тестов и Pull Request.** Не записывать секреты Cloudflare в публичный JavaScript.
